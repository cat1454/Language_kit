# Learning Flow

## Principle

Listening must happen before roleplay and writing.

Listening gives the learner input in context. The learner hears useful chunks, tone, sequence, and response patterns before producing language.

## End-To-End Flow

```text
choose topic
-> define real situation
-> pre-listening
-> listening input
-> while-listening checks
-> post-listening chunk mining
-> roleplay
-> writing task
-> feedback
-> listening log + error log
-> retry drills
-> progress measurement
-> next topic
```

## Stage Details

### 1. Choose Topic

The learner chooses a topic and context, for example:

- English B1
- workplace communication
- reschedule a meeting

### 2. Define Real Situation

The app turns the topic into a concrete situation:

```text
You need to move a meeting with a colleague because of a scheduling conflict.
```

### 3. Pre-Listening

The learner sees:

- context brief
- prediction questions
- key phrases to notice

The goal is preparation, not full explanation.

### 4. Listening Input

The learner listens to a short realistic script, ideally 60-90 seconds.

The full transcript should remain hidden until after listening checks.

### 5. While-Listening Checks

The learner answers:

- gist questions
- detail questions
- key phrase recognition items

Track:

- answer correctness
- replay count
- missed details
- phrases not recognized

### 6. Post-Listening Chunk Mining

The app extracts 5-8 useful chunks from the listening input.

Each chunk should include:

- phrase
- meaning
- example
- source line or context
- target reuse task

### 7. Roleplay

The learner roleplays in the same situation. The roleplay should reuse the listening context and target chunks.

Initial MVP roleplay is text-based.

### 8. Writing

The learner writes a short output continuing the same situation, for example:

- email
- chat message
- meeting confirmation
- short explanation

The writing task should require reuse of target chunks.

### 9. Feedback

Feedback covers:

- listening comprehension
- speaking or roleplay quality
- writing quality
- chunk reuse
- errors worth logging
- one retry drill

### 10. Logs

The app stores:

- listening log
- roleplay transcript
- writing submission
- error log
- retry drill source

### 11. Retry Drills

Retry drills should turn feedback into action:

- listen again with a variation
- repeat useful chunks
- rewrite the answer
- answer a similar situation

### 12. Progress Measurement

Track progress across sessions:

- completed topics
- listening accuracy
- repeated errors
- chunk reuse
- retry completion

## Sample Topic Flow

Topic: Reschedule a meeting.

1. AI creates a workplace situation.
2. Learner listens to a 60-90 second conversation.
3. Learner answers gist/detail/key phrase questions.
4. App mines chunks such as:
   - Could we reschedule?
   - I have a scheduling conflict.
   - Would Friday at 3 work for you?
   - Sorry for the inconvenience.
   - Thanks for understanding.
5. Learner roleplays as the person requesting the change.
6. Learner writes a confirmation email.
7. Feedback and retry drills are stored.
